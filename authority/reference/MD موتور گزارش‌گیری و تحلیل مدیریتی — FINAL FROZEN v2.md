# MD موتور گزارش‌گیری و تحلیل مدیریتی — SAMA

**پروژه:** سامانه املاک سازمان فرهنگی هنری شهرداری تهران (SAMA)  
**حوزه:** Report Engine / Analytics / Export / Drill-down  
**وضعیت:** `FINAL FROZEN`  
**نوع سند:** مشخصات معماری، تجربه کاربری، Query Model، Export و گزارش‌های عملیاتی/مدیریتی

---

# 1. هدف

SAMA دارای یک موتور گزارش‌گیری مرکزی و مشترک است.

تمام موارد زیر باید از **یک Query و یک Dataset معتبر واحد** تغذیه شوند:

```text
Screen Table
KPI
Chart
Drill-down
Excel
PDF / Print
Snapshot
```

هیچ بخش نباید برای یک مفهوم، منطق شمارش یا Dataset جداگانه داشته باشد.

---

# 2. اصل Single Dataset

قاعده قطعی:

> عددی که در KPI نمایش داده می‌شود، رکوردهایی که در Drill-down باز می‌شوند، داده‌ای که در جدول صفحه دیده می‌شود و خروجی Excel/PDF همان گزارش باید از یک Dataset واحد تولید شوند.

مثال:

```text
Candidate = 24
```

کلیک روی 24:

```text
Exactly 24 records
```

Excel همان گزارش:

```text
Exactly the same 24 records
```

# 3. جایگاه Report Engine

Report Engine یک سرویس مرکزی است و Dashboard، صفحات لیست و مرکز گزارش‌ها از آن استفاده می‌کنند.

معماری:

```text
Report Definition Registry
        ↓
Query Service
        ↓
Validated Filters
        ↓
Canonical Dataset
        ↓
Column Projection
        ↓
Grouping / Aggregate
        ↓
Screen / KPI / Chart
        ↓
Excel / PDF / Print
        ↓
Optional Snapshot
        ↓
Audit
```

# 9. ستون خالی سفارشی

کاربر می‌تواند در گزارش یک یا چند:

```text
CUSTOM_BLANK_COLUMN
```

اضافه کند.

برای هر ستون خالی:

- عنوان سفارشی
- عرض ستون
- محل قرارگیری
- ترازبندی
- نمایش در Excel
- نمایش در PDF / Print

قابل تعیین است.

مثال:

```text
توضیحات جلسه
نظر مدیر
پیگیری
توضیحات
```

محتوای این ستون‌ها در Dataset و دیتابیس SAMA ذخیره نمی‌شود.

هدف:

- یادداشت دستی روی نسخه چاپی
- تکمیل بعدی در Excel
- ایجاد فضای کنترل‌شده در گزارش

اگر کاربر نیاز به ذخیره یک داده واقعی داشته باشد، باید Field رسمی در Data Model تعریف شود و نباید از ستون خالی به‌عنوان Shadow Data استفاده شود.

---

# 10. ذخیره ستون خالی در Saved Report

# 14. فیلتر سلسله‌مراتبی سازمانی

# 15. Multi-select مناطق

فیلتر Region باید Multi-select باشد.

مثال:

```text
منطقه IN [1, 3, 5, 15]
```

انتخاب چند منطقه به‌صورت OR در همان بُعد انجام می‌شود.

---

# 16. Multi-select مراکز

فیلتر Center نیز Multi-select است.

کاربر می‌تواند با Search نام مرکز را پیدا و انتخاب کند.

مثال:

```text
Center IN [
فرهنگسرای خاوران,
فرهنگسرای معرفت,
فرهنگسرای رسانه
]
```

---

# 17. منطق Region + Center

برای جلوگیری از ابهام، UI سه Mode دارد:

## Mode A — تمام مراکز مناطق انتخاب‌شده

```text
ALL_CENTERS_IN_SELECTED_REGIONS
```

## Mode B — فقط مراکز انتخاب‌شده

```text
ONLY_SELECTED_CENTERS
```

## Mode C — مناطق انتخاب‌شده + مراکز اضافه

```text
SELECTED_REGIONS_PLUS_EXTRA_CENTERS
```

قبل از اجرای گزارش، SAMA خلاصه منطقی فیلتر را به زبان فارسی نمایش می‌دهد.

کاربری = ورزشی

تمام کدهای ورزشی در همه مناطق و مراکز.

---

# 20. نمونه فیلتر فضاهای آموزشی چند منطقه و مرکز

مثال:

```text
کاربری = آموزشی
Region IN [R1, R2, R3, R4]
+ چند مرکز خاص
ScopeMode = SELECTED_REGIONS_PLUS_EXTRA_CENTERS
```

سامانه باید تمام رکوردهای مطابق این Scope را برگرداند.

---

# 21. منطق فیلترها

قاعده پیش‌فرض:

- OR درون یک بُعد
- AND بین ابعاد مختلف

مثال:

```text
Usage IN [آموزشی]
AND
Region IN [1, 3, 5, 15]
AND
TransactionLevel IN [متوسط, عمده]
```

برای Scopeهای خاص، Mode منطقه/مرکز اعمال می‌شود.

---

# 22. خلاصه فیلتر

قبل از Print/Export، فیلتر به زبان قابل فهم نمایش داده می‌شود.

مثال:

```text
کاربری: آموزشی
مناطق: 1، 3، 5، 15
مراکز اضافه: خاوران، معرفت
سطح معامله: متوسط و عمده
وضعیت فضا: فعال
```

همین Summary روی گزارش چاپی در صورت انتخاب کاربر قابل نمایش است.

# 23. صفحه فضاها — نمایش سوابق کارشناسی

# 24. اطلاعات هر سابقه کارشناسی در لیست فضاها

برای هر Slot کارشناسی حداقل این داده‌ها قابل نمایش است:

- تاریخ کارشناسی
- مبلغ کارشناسی
- نام کارشناس
- سطح معامله مرتبط با همان کارشناسی

در صورت نیاز ستون‌های این Pack می‌توانند باز/بسته شوند.

---

# 25. عدم بازنویسی تاریخچه کارشناسی

Previous Appraisal 1 و 2 باید از رکوردهای واقعی تاریخی خوانده شوند.

هیچ مقدار تاریخی از آخرین کارشناسی کپی یا بازسازی نمی‌شود.

اگر کمتر از دو سابقه وجود داشته باشد، Slot مربوط خالی نمایش داده می‌شود.

---

# 26. سطح معامله تاریخی کارشناسی

اگر سطح معامله در زمان کارشناسی Snapshot/ثبت شده باشد، همان مقدار تاریخی نمایش داده می‌شود.

Rule فعلی نباید برای بازنویسی سطح تاریخی استفاده شود.
