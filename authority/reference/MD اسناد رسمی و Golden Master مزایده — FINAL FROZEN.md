# MD اسناد رسمی و Golden Master مزایده — SAMA

**پروژه:** سامانه املاک سازمان فرهنگی هنری شهرداری تهران (SAMA)  
**حوزه:** اتوماسیون اسناد رسمی مزایده، قراردادهای نمونه، روکش پاکت‌ها، صورتجلسات و Golden Master  
**وضعیت:** `FINAL FROZEN`  
**نوع سند:** مشخصات الزام‌آور طراحی و پیاده‌سازی  
**اصل حاکم:** هیچ کدنویسی Production برای Document Engine مجاز نیست مگر بر اساس این سند و پس از عبور موفق نمونه‌های Golden Master از آزمون چاپ.

---

# 1. هدف

هدف این مرحله ایجاد یک موتور تولید سند قطعی، قابل ممیزی و بدون خطای محتوایی برای مزایده است؛ به‌گونه‌ای که:

- اطلاعات ثابت سازمان فقط یک‌بار ثبت شود؛
- اطلاعات هر کد فضا فقط از منبع اصلی همان کد خوانده شود؛
- اطلاعات دوره مزایده فقط یک‌بار ثبت شود؛
- فقط محل‌های مشخص‌شده توسط مالک فرآیند به‌صورت خودکار تکمیل شوند؛
- متن ثابت اسناد توسط SAMA تغییر نکند؛
- همه اسناد با یک Dataset واحد و Snapshot واحد تولید شوند؛
- خروجی چاپی از نظر صفحه‌بندی، ترتیب، خوانایی و ثبات قابل اعتماد باشد.

---

# 2. منابع رسمی

سه خانواده مستقل اسناد رسمی داریم:

1. **فضای تجاری**
2. **فضای کافه**
3. **فضای ورزشی**

برای هر خانواده، منابع رسمی شامل اسناد مزایده و نمونه قرارداد همان دسته است.

هیچ Template از دسته دیگر به‌عنوان جایگزین استفاده نمی‌شود.

---

# 3. اصل طلایی تکمیل خودکار

قاعده قطعی:

> **فقط محل‌هایی که در منابع ارسالی توسط کاربر هایلایت شده‌اند مجاز به تکمیل خودکار توسط SAMA هستند.**

هر محل غیرهایلایت‌شده یکی از دو حالت است:

- متن ثابت؛
- جای خالی که باید همان‌طور خالی بماند.

حتی اگر SAMA مقدار آن را بداند، حق ندارد مقدار را در محل غیرهایلایت‌شده وارد کند.

---

# 4. متن ثابت

تمام متن‌های غیرهایلایت‌شده:

```text
STATIC_TEXT
```

هستند.

SAMA در Runtime حق ندارد:

- جمله‌ای اضافه کند؛
- جمله‌ای حذف کند؛
- عبارت حقوقی را بازنویسی کند؛
- ترتیب مواد را تغییر دهد؛
- بند یا تبصره را جابه‌جا کند؛
- مفهومی را خلاصه یا تفسیر کند.

---

# 6. Page Order Lock

ترتیب صفحات هر سند رسمی قفل است.

```text
PAGE_ORDER = LOCKED
```

هیچ صفحه‌ای در Runtime جابه‌جا نمی‌شود.

---

# 7. Atomic Pages

صفحات زیر حتماً یک صفحه مستقل هستند:

- برگه منع مداخله؛
- روکش پاکت الف؛
- روکش پاکت ب؛
- روکش پاکت ج؛
- هر صفحه‌ای که در Master به‌عنوان Atomic Page تعریف شود.

Rule:

```text
NO_PAGE_SPILL
NO_PAGE_MERGE
NO_PAGE_SPLIT
```

اگر محتوا باعث سرریز شود، Final Export متوقف می‌شود.

قواعد:

- نوشته زیر لوگو جداگانه تایپ نمی‌شود؛

- لوگوی مشابه یا بازطراحی‌شده ممنوع است؛
- نماد و نوشته رسمی به‌عنوان یک Asset واحد استفاده می‌شوند.

```text
OFFICIAL_LOGO = EXACT_SOURCE_ASSET
```

# 16. Field Registry

فیلدهای خودکار با شناسه پایدار تعریف می‌شوند.

گروه‌های اصلی:

```text
ORG-*
AUC-*
SPACE-*
LOT-*
SESSION-*
```

فیلدهای شرکت‌کننده و دبیرخانه، مگر در محل هایلایت‌شده و صراحتاً مصوب، خودکار تکمیل نمی‌شوند.

---

# 17. Single Source of Truth

هر Field فقط یک Owner دارد.

نمونه:

```text
SPACE-001 ← CommercialSpace.space_code
AUC-014   ← AuctionPeriod.opening_date
LOT-003   ← AuctionLot.guarantee_amount
ORG-*     ← OrganizationProfile
```

Template حق تعریف منبع دوم برای همان Field را ندارد.

---

# 18. مبلغ سپرده

هیچ فرمول پیش‌فرضی برای محاسبه آن وجود ندارد.

SAMA فقط مقدار ثبت‌شده مصوب را در محل‌های هایلایت‌شده تکرار می‌کند.

# 34. PowerPoint جلسه

PowerPoint جلسه از Dataset همان AuctionPeriod/AuctionLot استفاده می‌کند.

اما PowerPoint یک Template مستقل از اسناد حقوقی است و نباید متن اسناد رسمی را تغییر دهد.

## 34.1 جایگاه عکس در PowerPoint

در Slide هر AuctionLot می‌توان یک **Image Placeholder اختیاری** در Template داشت.

Rule:

```text
Image Placeholder = Manual Presentation Element
CommercialSpace Photo Field = Prohibited
Database Image Source = None
```

- عکس بخشی از Field Registry عملیاتی CommercialSpace نیست.
- سامانه هیچ عکس فضای تجاری را نگهداری نمی‌کند.
- Placeholder پس از تولید PowerPoint توسط کاربر به‌صورت دستی قابل تکمیل است.
- نبود عکس، Missing Field محسوب نمی‌شود و Final Export را Block نمی‌کند.
- Image Placeholder نباید به اسناد حقوقی DOCX/PDF سرایت کند.

# 45. تصمیم‌های نهایی FROZEN

1. فقط هایلایت‌ها توسط SAMA تکمیل می‌شوند.
2. جای‌خالی غیرهایلایت‌شده خالی می‌ماند.
3. متن غیرهایلایت‌شده ثابت است.
4. اصلاح ظاهر و نیم‌فاصله مجاز است.
5. تغییر معنایی ممنوع است.
6. ترتیب صفحات قفل است.
