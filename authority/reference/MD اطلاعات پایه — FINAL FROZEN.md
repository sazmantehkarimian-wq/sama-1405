# MD اطلاعات پایه — FINAL FROZEN

**پروژه:** سما  
**ماژول:** اطلاعات پایه  
**وضعیت:** `FINAL FROZEN`  
**نوع Freeze:** دامنه، داده، رفتار و منطق کاری  
**استثنای باز:** Visual Normalization طبق `SAMA-DS 1.0`

---

## 1. اصل Freeze

از تاریخ تصویب این سند، محتوای ماژول «اطلاعات پایه» از نظر دامنه، داده‌های مرجع، رفتار و منطق کاری مصوب و FROZEN است.

تغییر محتوایی یا رفتاری فقط با درخواست مستقیم Owner مجاز است.

این Freeze به معنی نهایی‌شدن ظاهر فعلی نیست. ظاهر ماژول باید در مرحله جداگانه، بدون تغییر منطق و داده، با Design System مرکزی سما Normalize شود.

## 3. اطلاعات سازمان

شامل اطلاعات عمومی مشترک سازمان برای استفاده در فرم‌ها، اسناد و گزارش‌ها، از جمله:

- نام سازمان
- مدیریت
- اداره
- نشانی
- کدپستی
- تلفن اصلی
- فکس
- ایمیل
- وب‌سایت
- روزهای کاری
- ساعات کاری
- محل دبیرخانه
- سایر اطلاعات عمومی مشترک مورد نیاز خروجی‌های رسمی

---

## 4. مناطق و مراکز

- سطح مرجع شامل ۲۲ منطقه و ۱۶ مرکز ویژه است.
- جمع کل مرجع: ۳۸ رکورد.
- زیرواحدهایی مانند خانه فرهنگ، کتابخانه و مجتمع در این سطح رکورد مستقل نیستند.
- داده‌های مرجع فقط از منابع تأییدشده پروژه اخذ می‌شوند.
- اصلاح املایی و نگارشی واضح مجاز است؛ اختراع داده ممنوع است.
- رکورد واقعی نباید حذف شود و سابقه باید حفظ گردد.

دفترچه تماس سازمانی برای مدیران، معاونان، رؤسا و مسئولان.

- مرکز

- نام و سمت مسئول
- تلفن همراه
- تلفن ثابت
- داخلی

تاریخچه نباید به‌صورت فیلد ورودی دستی به کاربر تحمیل شود.

- کمیسیون جاری معاملات
- امکان تعریف/ویرایش کمیسیون‌های تخصصی
- فعال / غیرفعال
- اعضا
- نقش عضو
- عنوان سازمانی

- جابه‌جایی ترتیب اعضا

عملیات جلسات، دعوت، صورتجلسه، مصوبات و Workflow در ماژول تخصصی «کمیسیون» انجام می‌شود، نه در اطلاعات پایه.

- فرم‌ها ساده، کوتاه و اداری باشند.
- فیلد اجباری واضح باشد.
- Help Text کوتاه و قابل فهم باشد.
- Save / Cancel واضح باشند.
- هر داده فقط یک‌بار و در محل درست دریافت شود.
- واژگان فنی دیتابیسی در UI ممنوع است.
- Search و Filter مطابق استاندارد مرکزی سامانه باشد.
- PDF / Excel / Print از موتور گزارش مرکزی استفاده کند.

## 10. استثنای ظاهری ثبت‌شده

وضعیت ظاهری فعلی این ماژول هنوز `VISUAL NORMALIZATION PENDING` است.

اصلاحات آینده باید فقط در لایه Design System انجام شود و شامل این موارد باشد:

- یکنواخت‌سازی Page Header
- یکسان‌سازی Toolbar
- یکسان‌سازی Table / Form / Card
- استفاده از Component Registry رسمی
- اصلاح فاصله‌ها، اندازه‌ها و Hierarchy
- رعایت کامل `NO LOCAL REINVENTION`

این تغییرات مجاز هستند، مشروط بر اینکه داده، Workflow و منطق FROZEN را تغییر ندهند.
